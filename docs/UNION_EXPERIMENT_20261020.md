# 双路切分点并集：实现与随机demo测试

日期：2026-10-20，Asia/Shanghai。用户明确要求实现PySceneDetect和RallyClip
切分点并集、随机选一个demo测试并评价。没有修改之前独立路线的决策逻辑。

## 实现口径

`src/rallycut/fusion.py` 合并同一源视频的两路候选：RallyClip的开始/结束点，
以及PySceneDetect显式剪辑点。默认1秒容差，剪辑点贴近动作边界时归并到该
动作边界，原始时间、来源和事件类型保留。不会传递地把相邻不同动作起止
吞成一点，也不会删除短于1秒的区间；短段显式 `short_fragment=true`。
来源一致性仅是共识标记，没有冒充校准后的置信概率。

完整并集保存在 `boundaries` 与 `timeline_segments`，包括动作候选之外
的剪辑点。后者划分整个[0,duration]、无重叠无空洞，不把“未检出动作”
等同“确定空闲”。`rallies`只保存有RallyClip支持、被并集进一步拆开的区间；
其余分区保存在 `outside_activity_segments` 并标为待确认。报告和视频
展示完整分区，灰色表示未确认，不将它们宣传为真实回合。

新增命令 `rallycut fuse` 和一视频入口 `tools/run_union.py`。保存来源CSV、
完整分区CSV、JSON及复核网页，可选烧录MP4。原始动作与剪辑结果分别保留，
人工标注只在推理和融合完成后用于对照。没有人工标签时，评测为缺省/null，
不会生成虚假的准确率。

目前两个识别子进程分别解码，尚未实现共享解码优化；CPU两线程配置不等于
业务服务器的两个vCPU配额，也没有进行业务服务器容量测试。无GPU或API调用。

## 随机样本实际结果

同一官方RallyClip v0.5.0权重，5fps/416输入；PySceneDetect沿用此前edited
诊断参数，4fps/320宽。默认归并1秒、短段1秒，未依据本片标签/结果调参。

| 输出 | 时间（秒）/数量 |
| --- | --- |
| PySceneDetect剪辑点 | 35.75，共1个 |
| RallyClip候选1 | 37.3628—38.2618，仅0.899秒 |
| RallyClip候选2 | 39.8752—70.3822 |
| 完整并集边界 | 35.75、37.3628、38.2618、39.8752、70.3822 |
| 完整分区 | 6段，含4段没有动作支持的待确认区间 |
| 动作支持区间 | 2段，本片没有增加内部动作区间切分 |
| 双路共识边界 | 0个 |
| 小于1秒分区 | 2段，均保留；其中1段有动作支持 |

评价：剪辑支路保住了动作模型没有报告的35.75秒构图跳变，但前半段持续
击球没有得到动作模型支持；后半段也出现约0.9秒动作碎段。因此并集能补充
候选边界，不能自动修复动作漏识，更不能证明候选之间都是独立回合。
远景/斜侧机位和人物尺度可能影响模型，但未做消融，不能确定归因。
此随机样本表现不理想，尚不能直接用于无人复核的自动剪片。

没有完整独立回合标签，不报告该片precision、recall、F1或回合数量准确率。
